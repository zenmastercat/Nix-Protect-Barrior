# Security review and fixes, 2026-11-17

Record of the review of Nix-Protect-Barrior commit `fcb4a0f`, the upstream research done at the same time, and the changes in commit `536ce08`. Machine-specific findings from the audit of the first installation are not published here.

## Code review of `fcb4a0f`

Result: 0 critical, 4 high, 4 medium, 3 low (plus smaller points). All are fixed in `536ce08`.

### High

| # | Problem | Fix |
|---|---|---|
| H1 | Approvals were keyed by the flake path. The automatic upgrade uses a store path that changes with every configuration edit, so each edit reset the baseline, and the next unattended run approved everything. | One approval per host (`approved/<host>.json`). Approvals are never saved automatically. |
| H2 | The automatic-upgrade gate ran with `--fast` (no closure scan) and checked the lock **before** `nixos-rebuild --update-input` changed it, so the revision that was built was never checked. | The upgrade script updates the inputs in a temporary copy, freezes it, runs the full gate on it, and builds that frozen copy. |
| H3 | `extra-substituters`, `extra-trusted-public-keys`, `extra-trusted-users` and `nix.extraOptions` (appended verbatim to `nix.conf`) bypassed the cache, key and trusted-user checks. | The gate folds `extra-*` and `extraOptions` into its checks; module assertions refuse them; `include` lines in `extraOptions` are refused. |
| H4 | Turning off a single protection (kernel settings, SSH closure, audit, verify, the upgrade gate, a local-only port) passed the gate. | The running policy stores a snapshot of every switch; the gate fails on any weaker value unless that exact configuration is approved. |

### Medium

| # | Problem | Fix |
|---|---|---|
| M1 | `npb-rebuild` checked the flake folder and then built it again from the same user-writable folder (time-of-check/time-of-use). | `npb-check archive` copies the flake into the store once; the gate and `nixos-rebuild` both use that copy. |
| M2 | Approval was non-interactive (`--npb-approve`) and could widen trust in one command. | `--npb-approve` removed. Approval needs a terminal and asks for `APPROVE`, or `WIDEN` when caches, keys, trusted users or protections change. |
| M3 | The audit reported the configuration, not the live firewall, so missing rules went unnoticed. | The audit reads `iptables`/`ip6tables` (or the nft table) and reports a missing local-only rule as high. Local-only ports require the firewall to be on (assertion). |
| M4 | Docker-published ports are NATed before the host firewall, so local-only rules do not cover them. | `dockerLocalOnly` also binds new compose networks to 127.0.0.1; a Docker-published local-only port is a high audit finding. Explicit `0.0.0.0` mappings remain a documented limit. |

### Low and smaller points

| # | Problem | Fix |
|---|---|---|
| L1 | A gate run without root could not read approvals and passed anyway. | Unreadable or missing approvals block. |
| L2 | First install trusted the candidate configuration's own policy and saved a baseline automatically. | First install still checks against the candidate's policy (nothing else exists yet), but saving the baseline needs `barrier-approve`. |
| L3 | Root tools followed symlinks in watched home files, and printed user-controlled names as is. | Files are read with `O_NOFOLLOW` (symlinks are recorded by their target); control characters are stripped from messages. |
| L4 | `NPB_POLICY` / `NPB_STATE_DIR` were honoured as root; firewall rules could be inserted twice; the persistence watch list missed common spots. | Root ignores the overrides; rules are deleted before they are inserted; the watch list adds git config, fish functions, compositor configs and `~/.local/bin`. |

## Upstream research

| Finding | Effect | Action |
|---|---|---|
| Nix daemon advisories of 2026-10-13: CVE-2026-110450 (high: unprivileged daemon clients can corrupt store paths through the repair flag and get root), CVE-2026-110449, -110452, -110453. Fixed in 2.34.9, 2.35.3, 2.31.6, 2.30.6, 2.28.8. | Restricting `trusted-users` alone does not stop a local user from getting root on an unpatched Nix. | `build.requirePatchedNix` (default on): the module refuses a vulnerable `nix.package`; the audit checks the running Nix. |
| Docker's `ip` daemon option covers only the default bridge. | Compose networks still published on all interfaces. | `default-network-opts.bridge."com.docker.network.bridge.host_binding_ipv4" = "127.0.0.1"`. |
| Each trusted signing key is a trust anchor; a key with no official source widens trust. | Fake or unknown keys must not be trusted. | `build.allowedPublicKeys` allowlist; INSTALL.md shows how to verify a key against real signatures. |
| Hardening settings that break a desktop: disabling user namespaces (Steam/bubblewrap, Nix sandbox), `ptrace_scope` 2 or 3, `perf_event_paranoid` above 2 (profilers), `ip_forward=0` (Docker), `ia32_emulation=0` (32-bit Steam), `lockKernelModules`. | Avoided. | The runtime layer sets none of them; `ptrace_scope=1` can be turned off. |
| `vulnix` matches only NVD CPE data, which NIST no longer enriches for most CVEs since 2026-04. | A CVE scan with it would give false comfort. | Not included. |

## Tests after the fixes

- `unit`: 23 tests of the gate rules, including `extra-*`, `extraOptions`, weakened protections and approvals.
- `assertion-control`: a clean configuration evaluates. It proves the assertion tests below fail for the right reason (an earlier version passed only because the test configuration itself was incomplete).
- `assertion`, `assertion-extra-options`, `assertion-old-nix`: an unknown cache, an `extraOptions` trusted user and Nix 2.34.8 are refused.
- `vm` (two machines): only root is trusted; kernel settings; the attacker cannot reach a local-only port or SSH while another port stays open; the rules survive a firewall reload and a deleted rule is reported; the short commands exist; the audit reports a planted setuid file and an autostart entry; the store check passes on a clean store and finds a tampered path.

## Known limits

See the README, section *Limits*. In short: only `npb-rebuild`/`rebuild` and the automatic upgrade are gated; SSH closure is a firewall rule; explicit `0.0.0.0` Docker mappings still publish; browser extensions may call Ollama when `ollamaLocalOrigins` is on.
